Verdict:

- **SwiftShader is run-to-run deterministic**, so the golden pixel tolerance is **exact (0)**. The state tolerance is 1e-9, applied as `|a−b| ≤ 1e-9·max(1,|a|,|b|)`; the measured maximum is 0.
- v2 has a **render-history dependence**. The face's scratch canvas `Face.tmp` keeps its 1024×512 size, but `tube()` clears only the corner it uses, so a blurred `drawImage` at a fractional offset reads stale texels. Clearing `Face.tmp` restores the cold result exactly. This is why the goldens are cold renders and why the sequential reference exists.

## Review round 3: the four gaps and their fixes

### Gap 1: the wall-clock guard could be bypassed with ordinary spellings

The reviewer was right. The round-2 scanner matched text with a regular expression and lexed regex literals heuristically:

- It skipped a name preceded by `.`, so `window.window.Date.now()`, `frames.Math.random()` and `document.defaultView.performance.now()` passed.
- It allowed only one plain `globalThis.`/`window.`/`self.` prefix, so `globalThis?.Math.random()` passed.
- It did not decode identifier escapes, so `Math.random()` passed.
- It mistook `{} / Math.random() / 1` for a regex.
- It let `Function.prototype.constructor(…)` through.

Round 2's claim to catch "every spelling" was false.

Fix: `render/lib/determinism-scan.mjs` is rewritten on a real parser, Acorn 8.18.0. It is vendored as `render/lib/vendor/acorn.mjs`, unmodified, MIT, copied from the machine's `/opt/node-tools`; no network install was needed. The scanner judges the syntax tree:

- **Escapes and lexing:** the parser decodes identifier escapes and cannot confuse a regex with a division. A file that does not parse is a finding.
- **Names on any receiver:** `Math`, `Date`, `performance`, `crypto` and `Temporal` are recognised by **name** as a variable or as a property of any object, through `.x`, `?.x` or a constant key. Constant keys are folded: literals, `'M'+'ath'`, templates and single-assignment `const`s. So no prefix chain matters. The allowed uses are unchanged: Math members except `random`, `new Date(args)`, `Date.UTC`/`parse`, `crypto.subtle`, `typeof`/`instanceof`, and assignment, which is how the virtual clock installs itself.
- **The global object** may not be indexed by a computed key or handed to `Reflect`/`Object`. The global object includes local aliases (`const g = window`, `f(g = globalThis)`) and top-level `this` in classic scripts.
- **Code from strings:** every syntactic route is a finding. That covers `eval`, `Function` (any use but `instanceof`), any `.constructor` access, string timers, computed `import()`/`Worker`/`require`/`importScripts`/`addModule`, `document.write`, `innerHTML`/`outerHTML`/`srcdoc` assignment, `insertAdjacentHTML`, `<script>` creation (or `createElement` with a computed tag), `on*` attributes, `javascript:` URLs and `node:vm`, `worker_threads`, `child_process`, `module` and friends. A sink used as a value (`const st = setTimeout`, `setTimeout.call(…)`) is a finding too.
- **More clocks:** `process.hrtime`/`uptime`, `node:perf_hooks`, node:crypto's random functions, `Temporal.Now`, Intl `format()` with no date, `event.timeStamp` and `document.timeline`.
- **Imports:** studio code that `engine/`/`composer/` import from elsewhere is scanned with the same rules, so a helper in `lib/` cannot carry `Date.now` in. Imports of the frozen v2 and the live app are hash-locked and are listed, not followed. Packages, URLs, absolute paths, files outside the studio and non-JS files cannot be imported.
- **HTML:** `<script>` bodies, `on*` handlers and `javascript:` URLs are scanned; JSON and shader blocks are skipped.

### Gap 3: npm's compile cache was hidden behind a wrong reason

The reviewer was right on every point. npm 10.9.4's `lib/cli.js` (lines 2–5) calls `module.enableCompileCache()` before it reads any configuration. Every studio `npm run …` therefore writes V8 bytecode for npm's own modules to `$TMPDIR/node-compile-cache` whenever they are not yet cached. npm runs outside the write jail, and round 2 exempted the whole directory with a false reason. Round 2's claim that "`npm run hm -- help` leaves nothing new" held only with a warm cache.

What I measured, writing only in WORK:

```
$ TMPDIR=$WORK/tmp/r3/tmpdir1 npm --logs-dir=$WORK/tmp/r3/logs run env   (a probe package in WORK)
child cache dir: undefined        → children do NOT inherit the cache (no NODE_COMPILE_CACHE in their env)
95 files under $TMPDIR/node-compile-cache/v22.22.0-x64-ac9e9e6b-0/
```

- **Key and header.** Node names each entry `crc32(<type byte>, <filename>)`, where type 0 is a CommonJS path and type 1 an ESM `file:` URL. 90 + 5 of the 95 names matched that formula. The 16-byte header holds the magic `0x8adfdbb2`, the source length and the source's CRC32, and all 95 matched an npm file exactly.
- **The host's cache is all npm.** All 612 entries in the host's `/tmp/node-compile-cache/v22.22.0-x64-ac9e9e6b-0` are npm's own modules.
- **No studio setting can stop it.** Only the caller's `NODE_COMPILE_CACHE`, `NODE_DISABLE_COMPILE_CACHE` or `TMPDIR` can change it, and `.npmrc` is read too late.

Fix (detect precisely, correct the record, offer an npm-free path):

- **The blanket `/tmp/node-compile-cache` exemption is gone.** A file under any `…/node-compile-cache/<dir>/<8 hex>` is accepted only if two checks pass: its name is Node's cache key for a file inside npm's installation (`findNpmRoots()`: the npm next to this node and every `npm` on PATH), and its header holds that file's exact magic, length and CRC32. Accepted entries are reported as `attributed`, never silently, and `hm guard` prints their count. Any other cache entry is a finding: a studio module's, a forged one, or one whose content does not match.
- `.npmrc`, the write-audit header and `CONVENTIONS.md` now say exactly this.
- **`node cli/hm.mjs test`** is the npm-free way to run the suites; `npm test` and the `test:*` scripts are aliases of it. Plain `node` writes nothing outside: the jail launcher is a plain node process, and children do not inherit npm's cache.

Evidence:

