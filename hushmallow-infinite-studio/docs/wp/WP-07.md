### 2. A frozen Mallow is never written in place

Noomi's asset folder is frozen. Without `--out`, both CLIs therefore derive into `WORK/derive/noomi/{assets,asset-qa}` and compare byte for byte with `assets/noomi/` and `output/asset-qa/`; exit code 1 means any byte differs. So the plain command `python3 -I tools/derive/derive_mallow.py --mallow noomi` *is* the regression gate that WP-30, WP-31, WP-41 and WP-51 must keep green. Every output path passes `assert_writable()`, and inside the jail the frozen paths are read-only at the kernel level as well.

New Mallows default to `assets/<id>/` and `output/asset-qa/<id>/`. Noomi keeps its legacy flat `output/asset-qa/`.

### 3. The shared asset gates (`gates.py`, written by `asset_qa.py` and `derive_mallow.py --gates`)

| Gate | Measures | Default threshold (from) |
|---|---|---|
| `integrity` | max \|clean − art\| outside the edit mask; alpha identical | 0; identical (plan §12) |
| `transparent_rgb` | pixels with alpha < 2 and RGB ≠ 0 | 0 (Loomi F9) |
| `band_energy` | RMS of DoG bands 1-2, 2-4, 4-8, 8-16 px per channel (R, G, B, Y), zone A and zone B over a reference ring of untouched skin; clipped channels are n/a | 0.85-1.15 (plan; Glitzi/Pipzi reports) |
| `repeat_patch` | max NCC of every 24 px zone-A patch (band 1-8) against all windows of untouched skin | ≤ 0.95 (plan; Glitzi report) |
| `ghost` | Pearson r of the clean luma with each old stroke's shape, per band (1.5-4, 4-12, 12-32), over its halo | \|r\| < 0.05 (plan; Loomi Q3) |
| `lighting_sweep` | the ghost test on the normal map lit from 8 azimuths at 35° | \|r\| < 0.05 (Blubi report) |
| `cheek_refit` | cheeks refitted on the clean body: centre and radius shift; sparkle count | ≤ 1 px, all present (plan; Loomi Q4; Blubi 1 % via `max_radius_rel`) |
| `residue` | mean clean − smooth surround in zone A / zone B per channel | ≤ 3 levels (Blubi report) |
| `boundary_step` | median signed low-pass step across the edit-mask and zone-A edges (local-linear fit per side) | ≤ 2 levels (Loomi Q2) |
| `colour_match` | mean dE2000 of the low-passed edit region vs the smooth surround | < 2 (Pipzi report) |
| `cross_profiles` | cross-stroke luma and G profiles over ±60 px, max deviation from a line | ≤ 1.5 levels (Blubi report) |
| `texture_period` | cell period (or correlation length) inside vs outside | ±15 % (Glitzi/Pipzi reports) |
| `glint_density` | small bright glints per 10k px inside vs outside | ±25 % (Glitzi/Pipzi reports) |
| `reproducibility` | byte identity against `--expect` | identical (plan) |

A config's `qa` section overrides any threshold (`gates`), picks the enforced gates (`enforce`, default: all) and the stretch ranges of the channel sheet (`stretch`). Two new review images come with the gates: `qa-stretched-channels.png`, which shows each channel stretched on its own (where Loomi's defects show), and `qa-lighting-sweep.png`.

**Verdicts: `pass | warn | fail | n/a`.** The four statistical gates estimate their own sampling noise:

- `band_energy`: a block bootstrap;
- `ghost` and `lighting_sweep`: 12 copies of each stroke template displaced by 2 halo radii, as a null distribution;
- `cross_profiles`: the spread between 6 stretches of the stroke.

A value outside the threshold but within noise is a `warn`, never a failure. An input that does not exist is `n/a`, never a silent pass. This is a deviation, explained below.

## Deviations from the plan, with reasons

1. **More modules than the plan lists.** Besides `common.py`, `derive_mallow.py`, `asset_qa.py`, the finders and `configs/noomi.json`, there are:
   - `pipeline.py` (the step order shared by derivation and standalone QA);
   - `gates.py`, `metrics.py` and `qa_draw.py` (asset_qa.py would have been about 900 lines);
   - `config.py`, `paths.py`, `lock.py`, `run_legacy.py` and `tests/`.

   All are under `tools/derive/**`, which is this package's file ownership.
2. **Noomi's config keeps the generator name `tools/derive_noomi_hires.py`**, because the face JSON's `_about` and `fields.edit` strings name it, and byte identity requires the same text. New Mallows default to `tools/derive/derive_mallow.py --mallow <id>`.
3. **The statistical gates have a `warn` verdict** instead of a bare threshold. On the synthetic *ideal* clean body, fixed thresholds failed:
   - band energy 8-16 px: 0.53;
   - the ghost 1.5-4 px band: \|r\| 0.0575;
   - cross-profile flatness: 3.6-6.7 levels.

   All three are sampling noise in thin regions, or the body's own low-frequency texture. With the noise estimates the ideal body passes or warns, while every injected fault and the art itself still fail. Without this, WP-30 and later would chase false failures.
4. **Reference regions leave out non-skin.** That covers the finder's sparkles and cheek discs, every pixel where a fitted cheek model exceeds 0.2 %, specular streaks (luma > 235, dilated 7 px) and the top dimple. The surround data for `residue` and `colour_match` excludes them too. A first version interpolated cheek pink into the face centre, which gave mean dE 4.1 on the ideal body.
5. **Noomi enforces only `integrity`.** Its other gates are reported as the calibration baseline above. Enforcing them would fail the approved, frozen assets.
6. **Default outputs for a frozen Mallow go to `WORK/derive/<id>/`**, with an automatic byte comparison, instead of the config's folders. Noomi's pack stays in the flat `output/asset-qa/`; new Mallows get `output/asset-qa/<id>/`.
7. **The tests are Python `unittest` under `tools/derive/tests/`**, run through `tests/run.py`. They are not wired into `hm test` (node:test), because `cli/commands/test.mjs` and `tests/` lie outside this package's file ownership.

## Open issues

1. **Wire the Python suite into `hm test`.** A one-line node:test wrapper (`tests/unit/derive-py.test.mjs` running `python3 -I tools/derive/tests/run.py --fast`, about 52 s on 1 thread) or a `derive` suite in `cli/commands/test.mjs` would do it. Also add an `hm derive` / `hm asset-qa` command (named in design-quality-first.md), for example `cli/commands/derive.mjs`. Both are left to the integrator or the CLI owner.
2. **The ghost, texture and residue gates exclude cheek areas;** the cheek-refit gate covers the cheeks. A ghost *inside* a cheek, like the Blubi prototype's "tadpole" at the outer eye ends, is only covered by `cheek_refit`, the stretched-channel sheet and the contrast-boost image. WP-30 should extend the ghost region into the cheek once the cheek is handled as an analytic layer.
3. **Byte identity is tied to the library versions** recorded in `derive-manifest.json` (numpy 2.5.3, OpenCV 5.0.0, SciPy 1.18.1, Pillow 12.3.0, zlib 1.3). An upgrade can change bytes and must be checked with the plain `derive_mallow.py --mallow noomi` before it lands.
4. **Gate cost is 46.7 s per Mallow**, mostly the displaced-template null distributions at the 12-32 px band. That is fine once per Mallow. It could be cut to about 15 s by computing the coarse band at quarter resolution.
5. **The Noomi baseline failures** (residue +20 R, band energy 0.41-0.69, repeat NCC 0.996, mouth cross-profile 4.7) are invisible in v2 because the face is drawn over them. They would show if a future face style left zone A uncovered (open eyes, a smaller glow). Flag this to WP-10/WP-32 (face) and to the owner before any Noomi expression exposes the bare clean body.
6. **`legacy_noomi.py` must never be run directly.** Its paths are relative to its own file, so it would write into `tools/assets/`. Use `run_legacy.py`; the module docstrings say so.
7. **Process note: a stray write, now cleaned.** Early in the package, two ad-hoc commands without `sys.dont_write_bytecode` (`numpy.show_config()`, which imports yaml, and `pip list`) wrote 18 cpython-313 bytecode files into `/usr/lib/python3/dist-packages/{yaml,pip}`. `hm guard` caught them. I removed exactly those 18 files (all created at 02:30:44 and 02:35:50, none existed at arming), and the guard is green again (146/146). `python3 -I` does not stop bytecode writes, so every entry script in `tools/derive` sets `sys.dont_write_bytecode = True` before importing anything. Inside the write jail such writes would fail harmlessly anyway.
