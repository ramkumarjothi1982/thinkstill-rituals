# Risk → fix table

Every risk and bug found in the v2 engineering audit (`docs/design/map-v2-code.md` §5, R1–R21), mapped to the work package that fixes it and to the check that proves the fix. Work packages are defined in `docs/PHASE2-PLAN.md`.

How to read the table:

- **Fixed in** is the package that owns the fix. Packages after a "+" carry part of it.
- *Inferred* means the plan does not tag the package with this risk id, but that package's acceptance criteria deliver the fix.
- **Proof** is the gate or test that must pass before the package can close.

A package closes a risk only when its report (`docs/wp/WP-xx.md`) cites the proof with measured numbers. It then sets **Status** to `fixed`. All frozen v2 files stay unchanged: every fix lands in the fork (`engine/`, `composer/`, `audio/score.mjs`, …).

## What WP-00 contributes to every row

- `qa/golden/v2/`: the reference every fix must reproduce. State within 1e-9 at 2,441 times, mesh hashes, sub-frame counts, the cue log, curves, `buildPlanV2`'s event list, and 16 lossless frames. It also holds the RGBA hashes of all 450 in-order frames, whose re-encode is bit-identical to the approved master.
- `tests/guard/*`: the frozen v2 (git-ignored files included) and the live app can't change, `engine/` and `composer/` can't read the wall clock, and nothing is written outside the studio and WORK anywhere on the machine (write audit). Studio entry points run in the write jail (`render/lib/write-jail.mjs`), where such writes fail outright.
- `render/lib/heavy-lock.mjs`: benchmark numbers for R1/R21 (WP-02) are only valid when taken under `--exclusive`.
